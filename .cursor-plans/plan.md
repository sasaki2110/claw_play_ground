# README.md 日本語訳 — 実装プラン

**関連**: [GitHub Issue #3](https://github.com/sasaki2110/claw_play_ground/issues/3)（README.md の日本語訳）

## 1. 目的と前提

- 現状の `README.md` は `create-next-app` 既定の英語テンプレート（Getting Started / Learn More / Deploy on Vercel 等）。
- リポジトリ利用者が本人のみであるため、**本文を日本語に置き換える**（または日本語版を主とする）ことで、ローカル開発の手順と参照リンクが読みやすくなることを目的とする。
- 技術名・URL・コマンドはそのまま維持し、説明文のみ自然な日本語にする方針が無難。

## 2. 作業手順（詳細）

### 2.1 事前確認

1. `README.md` の現行全文を確認する（未カスタマイズの Next.js 既定文か、プロジェクト固有の追記があるか）。
2. リポジトリ内で `README.md` を参照している CI・スクリプト・ドキュメントがないか検索する（通常は参照なしだが、リンク切れ防止のため確認）。

### 2.2 翻訳方針の決定

1. **単一ファイル**: `README.md` を日本語のみにする（Issue の意図に最も沿う）。
2. **二言語併記**（任意）: 英語 README を残したい場合は `README.en.md` を新設し、ルート `README.md` を日本語にする、など。Issue 文面は「日本語訳」のみのため、**既定は `README.md` のみ日本語化**とする。

### 2.3 本文の作成

1. 見出し構造（`## Getting Started` 等）を維持するか、日本語見出し（例: `## はじめに`）にするかを決める。GitHub 上の可読性のため、**見出しは日本語、公式ドキュメント名は括弧で英語併記**でもよい。
2. 次のブロックを日本語化する:
   - プロジェクト説明（Next.js / create-next-app への言及）
   - 開発サーバー起動手順とブラウザ URL の説明
   - `app/page.tsx` 編集・ホットリロードの説明
   - `next/font` と Geist に関する一文
   - Learn More の箇条書き説明
   - Vercel デプロイ案内
3. **コードフェンス内のコマンド**（`npm run dev` 等）は変更しない。
4. **リンク URL** は変更しない（公式ドキュメント・Vercel への導線を維持）。

### 2.4 品質チェック

1. Markdown の構文（見出し階層、リスト、コードブロックの言語指定）が壊れていないかプレビューで確認。
2. 誤字・表記ゆれ（「Next.js」の表記統一など）を確認。
3. 必要なら `npm run dev` 等でローカル動作は README 変更とは無関係だが、README に書いたコマンドが `package.json` の scripts と一致するか目視確認。

### 2.5 コミット・Issue クローズ

1. 変更は `README.md` のみ（方針により `README.en.md` を追加する場合はそのファイルも）。
2. コミットメッセージ例: `docs: README を日本語化` または `docs: translate README to Japanese`
3. Issue #3 を PR または直接コミットでクローズする場合は、コミットメッセージまたは PR 本文に `Fixes #3` 等を記載。

## 3. 影響範囲

| 対象 | 影響 |
|------|------|
| `README.md` | **主な変更対象**。表示言語が英語から日本語へ変わる。 |
| アプリケーションコード | **なし**。ビルド・実行結果に影響しない。 |
| `package.json` / 依存関係 | **なし**。 |
| CI / デプロイ | README のみの変更なら通常 **なし**。README をパースする特殊なワークフローがある場合のみ要確認。 |
| 外部ドキュメント | リポジトリ URL がそのまま README を指す場合、表示が日本語になる。**リンク先 URL は変えない**ため、外部からの「英語 README 前提」の期待がある場合のみ注意（本 Issue では個人利用前提）。 |

## 4. リスク

| リスク | 内容 | 緩和策 |
|--------|------|--------|
| 将来のコントリビュータ | 公開リポジトリで英語 README が一般的。将来他人が参加する場合、英語版がないと不便になる可能性。 | 必要になったら `README.en.md` を追加する。 |
| 用語の不正確さ | Next.js の公式用語と日本語説明の対応がずれる。 | 公式ドキュメントへのリンクを残し、固有名詞は原文に近い表記を維持。 |
| Markdown 破損 | 編集ミスでフェンスやリンクが壊れる。 | プレビュー確認、差分レビュー。 |

## 5. 注意点

- **翻訳対象**: 説明文のみ。パッケージ名、パス（`app/page.tsx`）、コマンド、URL は原則そのまま。
- **ライセンス表記**: 現行 README にライセンス節がなければ追加不要。別ファイルで管理している場合は README から重複させない。
- **プロジェクト固有情報**: 現状はテンプレート文のため、日本語化と同時に「このリポジトリ固有の目的・セットアップ」への差し替えは **Issue スコープ外**とし、依頼があれば別 Issue で扱う。
- **ブランチ**: 作業ブランチ `3-orchestrator` 上で実施する場合、マージ先（`main` 等）のポリシーに合わせて PR を切る。

## 6. 完了の定義（DoD）

- ルートの `README.md` が日本語で、開発開始・学習リソース・デプロイ案内の意図が英語版と同等に伝わる。
- Markdown が正しくレンダリングされる。
- 変更ファイルが意図どおり（基本は `README.md` のみ）に収まっている。
